# 강의 문장 패턴

강의 본문·퀴즈·그림 alt text 를 검수할 때 고치는 한국어 패턴이다. AI 가 쓴 티가 나거나 영어를 옮긴 티가 나는 문장, 뜻이 한 번에
잡히지 않는 문장을 모았다. 강의 구성과 형식 규칙은 [CONTRIBUTING.md](../CONTRIBUTING.md) 에 있다.

## 예고와 감싸기

| 패턴 | 나쁨 | 좋음 |
| --- | --- | --- |
| 본론을 대시·콜론 뒤로 미루는 예고 구문 | 핵심은 이것이다 — 오차가 쌓인다. | 오차가 쌓인다. |
| "답은/이유는 ~에 있다" | 이유는 계산 주기에 있다. | 계산 주기가 길면 ~ 하기 때문이다. |
| 서론 질문 바로 다음 문단을 답으로 툭 시작 | (무엇을 계산해야 할까?) 행렬과 vector 를 한 번 곱하면 된다. | 이 문제를 푸는 좋은 방법은 행렬과 vector 를 한 번 곱하는 것이다. |
| "X 가 좋은 예다" 같은 예시 앞 예고 | 카메라가 좋은 예다. 카메라에는 frame 이 둘 붙는다. | 카메라 하나에도 frame 이 둘 붙는다. |
| 절 끝의 구조 예고 | 하나씩 더해 가며 각 항이 고치는 문제를 본다. | (지운다) |
| 서술을 한 겹 감싸는 틀 | 놀라운 점은 정확도가 오른다는 것이다. / ~인 셈이다. | 정확도가 오른다. |
| "~가 ~에서 드러난다" | step 7 에서 online update 가 드러난다. | step 7 에서 online update 의 효과가 보인다. |
| 절을 이유와 동일시 | 다음 절이 그 이유다. | 그 이유는 다음 절에서 다룬다. |

## 문장 길이와 연결

- 한 줄짜리 단문을 연달아 끊지 않는다. 인과·대조·부연은 `~라서`, `~지만`, `~는데`, `~고` 로 한 문장에 묶는다. 반대로 한 문장에 절이
  넷 이상이면 나눈다.
  - 나쁨: "로봇은 0 m 에 있다고 알고 있다. 분산은 1 이다. 바퀴를 굴려 2 m 앞으로 갔다."
  - 좋음: "로봇은 0 m 에 있다고 알고 있고 그 분산은 1 인데, 바퀴를 굴려 2 m 앞으로 갔다."
- `~는데` 로 이은 문장을 두 개 연달아 쓰지 않는다.
- 관계없는 두 사실을 `~고` 로 잇지 않는다. 주어가 바뀌는 맨 절을 `~는데` 뒤에 붙이지 않는다.
- 예시를 규칙보다 먼저 두지 않는다. 규칙을 먼저 쓰고 예시는 `~라서` 로 잇는다.
- 다른 분야의 사례를 개념 설명 바로 뒤에 맨 문장으로 붙이지 않는다. 그 사례에 개념이 왜 들어맞는지(어떤 성질 덕분인지)를 한 문장 먼저
  쓰고 사례로 넘어간다. 나쁨: "이 값을 cosine similarity 라고 한다. CLIP 은 사진과 글을 vector 로 바꾼 뒤 cosine similarity 가 큰 쪽을
  고른다." 좋음: "길이와 상관없이 방향만 재는 값이라서 화살표로 그릴 수 없는 vector 에도 쓸 수 있다. 사진과 글을 함께 다루는 모델인
  CLIP 은 …"
- 연이은 문단을 같은 주어로 시작하지 않는다.
- "A 해야 해서 B" 의 A 가 왜 필요한지 독자가 모를 수 있으면, A 를 강제하는 전제를 먼저 쓴다. 나쁨: "CNN 이 지시를 모른 채 사진을
  요약하면 두 물건을 모두 적당히 담아야 해서 지시한 물건의 정보가 흐려진다." 좋음: "사진 요약은 크기가 정해져 있고, 지시를 모르는
  CNN 은 어떤 지시가 와도 같은 요약을 낸다. 요약 하나로 두 지시에 모두 답해야 하므로 두 물건을 다 담아 두어야 한다."
- 정리·법칙을 옮길 때는 "X 는 Y 도 Z 로 나타난다" 처럼 결과만 적지 않고, 무엇을 보고 무엇을 짐작하는지를 넣어 풀어 쓴다. 인용 출처는
  문장 머리가 아니라 뒷받침으로 붙인다. 나쁨: "확률 이론의 결과(Feller, 1949)에 따르면 noise 를 조금 더하는 step 은 되돌리는 step 도
  종 모양 하나로 나타난다." 좋음: "noise 를 조금만 더한 step 이라면, 더한 뒤의 값을 보고 더하기 전의 값을 짐작할 때 그 범위가 지금 값
  근처의 한 군데로 모인다. 조금밖에 움직이지 않았으니 바로 전에도 근처에 있었을 것이기 때문이다."
- "봉우리", "범위" 같은 분포 용어를 그림이나 숫자보다 먼저 꺼내지 않는다. 먼저 "섞은 뒤 값이 1.0 이면 섞기 전 값은 0.8 ~ 1.2 사이"
  처럼 후보를 숫자로 보이고, 용어는 그 분포를 그린 그림 옆에서 붙인다.

## 동사 생략(gapping)

절마다 서술어를 따로 쓴다. 본문뿐 아니라 표 칸, 퀴즈 보기, 그림 alt text, 참고 자료 줄에서도 같다.

| 나쁨 | 좋음 |
| --- | --- |
| x 는 2 를, y 는 1 을 더한다. | x 에는 2 를 더하고, y 에는 1 을 더한다. |
| 최고 속도는 X 이고, 평소 감속도는 Y, 허용 감속도는 Z 다. | 최고 속도는 X 이고, 평소 감속도는 Y 이고, 허용 감속도는 Z 다. |
| 보내기 전에 시작점을, 실행하는 동안 시간을 검사한다. | 보내기 전에 시작점을 검사하고, 실행하는 동안에는 시간을 검사한다. |
| OpenCV 는 Tsai, MoveIt 은 Daniilidis 다. | OpenCV 는 Tsai 방법을 쓰고, MoveIt 은 Daniilidis 방법을 쓴다. |
| X 일 수도, Y 일 수도 있는데 | X 일 수도 있고 Y 일 수도 있는데 |
| 2.2절이 X, 2.3절이 Y 다. | X(2.2절)와 Y(2.3절)를 본다. |

## 번역투

| 패턴 | 나쁨 | 좋음 |
| --- | --- | --- |
| "곧"·"즉" 을 i.e. 처럼 반복 | Δt = 0.01 초, 곧 1초에 100 번 | Δt 는 0.01 초다. 1초에 100 번 계산한다는 뜻이다. |
| 영어 콤마 동격 어순 | TCP 라는, 빠진 데이터를 다시 보내는 통신 | 빠진 데이터를 다시 보내는 TCP |
| 사물 주어 + "알려 주다" | 이 움직임은 z 에 대해 아무것도 알려 주지 않는다. | 이 움직임으로는 z 를 구할 수 없다. |
| "~에 대해 주는 식" | K 에 대해 주는 식 | K 를 정하는 식 |
| "~마다의" | 시각마다의 자세 | 시각마다 정한 자세 |
| "A 가 B 를 나누어떨어지게" | 주기가 시간을 나누어떨어지게 | 시간이 주기로 나누어떨어지게 |
| "X 를 Y 의 예로 따라가 본다" | 이 방법을 배달 로봇의 예로 따라가 본다. | (예고를 지우고 첫 절에서 예를 바로 꺼낸다) |
| 영어 형용사·관용구 직역 | 의미 정보, 욕심내어 뻗는다 | 관절 그룹처럼 URDF 에 없는 정보, 막힐 때까지 계속 뻗는다 |
| 불필요한 피동 | 갱신되어야 한다 | 갱신해야 한다 |
| 명사화 사슬 | ~의 부족을 메우는 데서 출발한다 | ~가 부족해서 ~ 한다 |

## 주어와 행위자

- 논문·문서는 실험의 주체가 아니다. "논문은 차를 몰았다" 대신 "저자들은 차를 몰았다", "논문에 따르면 ~" 으로 쓴다.
- 강의 이름을 행위의 장소로 쓰지 않는다. "[Kalman Filter] 에서 이 drift 를 바로잡는다" 대신 "이 drift 를 바로잡는 방법은
  [Kalman Filter] 에서 다룬다".
- 의인화하지 않는다. "filter 가 조용히 틀린 답을 낸다" 대신 "오류 메시지 없이 틀린 추정이 나온다", "detector 가 문이라고 말한다"
  대신 "detector 가 문을 감지한다".
- 선택·학습의 주어를 밝힌다. "384×384 는 오래 걸려서 224×224 를 골랐다" 대신 "저자들은 384×384 가 오래 걸려서 224×224 를 골랐다".
- 계산하는 쪽과 계산되는 쪽을 바로 세운다. "행렬이 점을 곱하면" 대신 "행렬을 점에 곱하면".
- 용어를 정의한 바로 다음 문장에서 그 용어를 설명할 때는 주어를 생략하지 말고 용어를 한 번 더 쓴다. 나쁨: "이 값을 cosine similarity
  라고 한다. 길이와 상관없이 방향만 재는 값이라서 …" 좋음: "… cosine similarity 라고 한다. cosine similarity 는 길이와 상관없이 …"

## 단어 선택

- 주기·빈도(Hz, tick, step)를 "속도"·"빠르기" 로 부르지 않는다. "1초에 몇 번" 으로 센다.
- "계산이 돈다", "PID 가 도는 자리" 같은 개발자 말버릇 대신 "1초에 수백 번 계산한다", "PID 가 맡는 일" 로 쓴다.
- 근거 없는 최상급("가장 많이 쓰이는")과 범위 나열("공장부터 드론까지 거의 모든 곳"), 의성어·의태어(휙, 부르르)를 쓰지 않는다.
- 이름 없이 뭉뚱그린 명사구 대신 실제 이름을 쓴다. "ROS 의 위치 추정 package" 대신 "`robot_localization`".
- vector·값·시간 구간을 "칸" 으로 부르지 않는다. "더할 이동량", "간격마다" 로 쓴다.
- accuracy 한계는 "~까지 틀릴 수 있다", precision 한계는 "흔들린다" 로 구분한다.
- 함수의 최댓값은 "많아야" 가 아니라 "최대" 로 쓴다.
- 측정량과 겹치는 관용구를 피한다. 경로 길이를 말하면서 "거리가 멀다" 를 쓰지 않는다.
- 조사와 붙어 다른 말로 읽히는 단어를 피한다. "길이 곧지 않다" 는 '길이' 로 읽히므로 "경로가 곧지 않다".
- 미분값을 1 단위 변화로 읽지 않는다. "w 를 1 늘리면 loss 가 13.33 준다" 대신 "늘린 양의 약 13.33 배만큼 줄어든다".
- technical term 은 본문·퀴즈·alt text 어디서나 영어 원어로 쓴다(node, pretrained, dataset).

## 정의와 대조

- 용어를 정의할 때 항목마다 서술어를 준다. "타원이 node, 네모가 topic 이다" 대신 "타원은 node 를 나타내고, 네모는 topic 을 나타낸다".
- 정의를 따옴표 물음이나 따옴표 구절로 감싸지 않는다. "'n 을 거쳐 가면 얼마쯤 들까' 의 어림값" 대신 "n 을 거쳐 갈 때 드는 비용의 어림값".
- 대조 문장 안에 괄호 정의를 끼우지 않는다. 용어의 두 뜻을 비교하면 본론 뜻을 바로 앞 예로 붙잡고, 다른 뜻은 문단을 나눈다.
- "A 는 X, B 는 Y" 대조에는 갈리는 이유 한 절을 붙인다.
- "~지만" 대조의 양쪽은 같은 축을 비교한다.
- 안 한 일을 먼저 부정해 한 일을 띄우지 않는다. "표를 만들지 않고 규칙으로 바로 쓴다" 대신 "표를 만들 필요 없이 규칙으로 바로 쓴다".
- 포기한 것이 없으면 "그 대가로" 가 아니라 "다만" 으로 쓴다.

## 숫자와 예시

- 예시 숫자는 표·식보다 먼저 어디서 왔는지(사람이 정한 값, 앞 절의 계산 결과, 학습된 값)를 밝힌다.
- 고른 예시 값은 "예를 들어", "이 예에서는 ~ 로 둔다" 로 표시한다. 그림 캡션과 alt text 에도 표시한다.
- 앞에서 구한 숫자를 다시 쓸 때는 그 자리에서 출처 계산을 한 번 더 적는다("이 점의 오차는 5 − 8 = −3 이므로").
- 앞에서 단위와 함께 나온 값을 다시 부를 때도 단위와 무엇의 값인지를 붙인다. 나쁨: "LiDAR 가 알려 준 2 와 1 로". 좋음: "LiDAR 가 알려 준
  앞쪽 2 m, 왼쪽 1 m 를".
- 논문 수치는 조건(누가 무엇을 했는지)과 전후 원래 숫자를 먼저 보이고 % 는 그 뒤에 둔다. 늘어난 것이 좋은지 나쁜지는 따로 밝힌다.
- 파라미터 이름과 기본값을 부사구 하나에 몰지 않는다. 파라미터가 하는 일과 기본값의 뜻을 절을 나눠 쓴다.
- bug·예외처럼 예상을 깨는 사실은 한 구절로 넣지 않는다. 무엇이 어떻게 됐는지, 그 결과, 누가 어떻게 대응했는지를 따로 문단으로 푼다.
- 작업 경위 괄호("(직접 계산했다)")를 붙이지 않는다. 계산임을 밝힐 때는 문장 안에서 "~로 계산하면" 으로 쓴다.

## 비유와 제목

- 비유는 직설 설명 뒤에 " ~ 와 같다" 한 문장으로만 붙인다. 비유로 설명을 시작하지 않고, 비유를 비유로 설명하지 않는다.
- 제목·소제목·표 라벨은 대상 이름을 그대로 적은 명사구다. 문장형, 물음형, "X: 비유 부제" 를 쓰지 않는다.
- 표 머리를 강의의 절 제목과 같은 말로 쓰지 않는다(`## 학습 목표` 가 있는 강의의 비교 표 열 "학습 목표" 대신 "학습 방식").

## 요약·확인 문제·퀴즈 해설

- 요약 bullet 에도 본문의 구체 예(숫자·결과) 하나를 남긴다. 추상어만 남으면 요약만 읽어서는 뜻이 잡히지 않는다.
- 확인 문제의 답은 문제의 표기에서 값을 꺼내는 단계 → 본문의 어느 규칙을 쓰는지 → 숫자를 넣은 식 순서로 쓴다. 계산이 두 번
  이상이면 표나 번호 단계로 나눈다.
- 확인 문제가 값 하나만 바꿀 때 "나머지는 위와 같다" 로 넘기지 않는다. 함께 바뀌는 값과 고정하는 값을 밝힌다.
- 퀴즈 해설은 정답이 왜 맞는지부터 쓰고, 오답마다 틀린 이유를 한 문장씩 붙인다. 오답 셋을 한 문장으로 묶거나 하나를 빼먹지 않는다.
- 두 양이 반대로 움직이는 문항(sequence 길이와 vocabulary 크기처럼)은 해설 첫 문장에서 두 양을 각각 정의한다.
- 정의 문항의 해설에는 그 방식이 왜 필요한지도 쓴다.

## 지시어와 그림

- 아직 나오지 않은 것을 가리키는 지시어(그림보다 먼저 나오는 "위 그림")를 쓰지 않는다.
- 다른 절(특히 사이에 심화 블록이 낀 절)의 예시를 다시 꺼낼 때는 맨 이름으로 시작하지 않는다. 지금 절의 개념이 그 예시에도 생긴다는
  문장으로 잇고 어디서 나온 예시인지 밝힌다. 나쁨: "calibration 에서 표식 두 개를 …" 좋음: "singular matrix 는 앞 절의 카메라
  calibration 에서도 생긴다. 위치를 아는 표식 두 개를 …"
- 문장을 지운 뒤에는 바로 뒤 문장을 다시 읽는다. "도"·"이" 가 가리킬 대상이 사라졌을 수 있다.
- 지도 사이트는 그림의 alt text 를 화면에 보여 주지 않는다. alt text 에 같은 말이 있다고 본문 설명을 지우지 않고, 그림 자체에 보이는
  내용일 때만 본문을 줄인다.
- 흔한 오해 상자의 사실 줄이 바로 위 문단을 되풀이하면 그 문단 쪽을 줄인다.
- 흔한 오해 상자의 오해 줄은 "~라고 생각하기 쉽다", "~로 읽기 쉽다" 로 감싸지 않고 믿는 내용 그대로 쓴다. 나쁨: "$\tau$ 는 작을수록 좋다고
  생각하기 쉽다." 좋음: "$\tau$ 는 작을수록 좋다."
